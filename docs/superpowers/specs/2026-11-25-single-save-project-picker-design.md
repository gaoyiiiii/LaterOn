# 单页添加时选择项目

用户已批准实施当前切片：侧栏点击添加、单页快捷键添加时，默认在当前网页打开现有选项目浮层，预选「等待整理」。确认前不保存，取消不添加；选择已有项目或新建项目后按现有流程保存。

## 方案与边界

- 复用 `quickSave` → `askFolderThenSave` → `picker-ui.js`，不新增另一套弹窗或样式。
- 不采用全新窗口：现有网页浮层已支持中英文、主题、取消、新建项目和保存反馈。
- 单页默认开启选组，预选空项目 ID；整窗添加继续使用上次项目。
- 保留设置开关：`askFolderOnSingleOptIn === true` 且开关为 `false` 表示用户明确关闭，继续直接添加。没有主动设置标记的旧值采用新的默认开启行为。
- 设置读取、监听和后台决策保持一致；保留迁移标记，不删除已有设置。
- 当前切片不调整字体、不改变批量添加默认项目、不改变已有重复网址处理语义。

## 验证

fork 已包含 Node 行为脚本，本地原始副本缺少这些脚本。使用 fork 的测试，在修改前复现默认不弹窗、误选上次项目；验证默认确认保存到等待整理、指定项目保存、取消、重复网址、明确关闭与旧设置迁移、侧栏和快捷键一致性，以及批量默认项目不变。执行全部 `tests/*.test.js`、manifest 解析与根目录 JS 语法检查。Chrome API 由测试替身模拟，不能把它描述为真实浏览器验收。
